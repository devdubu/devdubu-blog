# Next.js 기초

:::info 개요
**Next.js**가 해결하고자 하는 **SSR(Server Side Rendering)**과 **SEO(검색 엔진 최적화)** 문제, 그리고 기존 React(CSR)와의 차이점을 정리합니다.
:::

## 1. Next.js란?
React 기반의 프레임워크로, **프로덕션(Production) 레벨**의 애플리케이션을 구축하기 위해 필요한 기능(SSR, 라우팅, 이미지 최적화 등)을 기본 제공합니다.

## 2. 렌더링 방식 비교

### 2.1 CSR (Client Side Rendering)
- **방식**: 브라우저가 빈 HTML을 받고 JS를 실행하여 내용을 채웁니다. (React 기본)
- **장점**: 초기 로딩 후 인터랙션이 빠름.
- **단점**:
    - **SEO**: 크롤러가 빈 화면을 볼 수 있어 검색 엔진 노출에 불리함.
    - **초기 로딩**: JS 다운로드 전까지 화면이 하얗게 보임.

### 2.2 SSR (Server Side Rendering)
- **방식**: 서버에서 HTML을 완성하여 브라우저에 전달합니다. (Next.js)
- **장점**:
    - **SEO**: 완성된 HTML을 크롤러가 바로 수집 가능.
    - **FCP(First Contentful Paint)**: 유저가 콘텐츠를 즉시 볼 수 있음.
- **단점**: 서버 부하가 증가할 수 있음.

### 2.3 SSG (Static Site Generation)
- **방식**: **빌드 타임(Build Time)**에 HTML을 미리 생성하여 CDN에 캐싱합니다.
- **장점**: 서버 요청 없이 가장 빠른 속도 제공. (블로그, 문서 사이트에 적합)
- **단점**: 빌드 이후 데이터가 변경되면 다시 빌드해야 함 (ISR로 보완 가능).

:::tip 언제 무엇을 쓸까?
- **SSG**: 마케팅 페이지, 블로그 게시글, 도움말 문서 (변경 빈도 낮음)
- **SSR**: 소셜 미디어 피드, 주식 차트 (실시간 데이터 중요)
- **CSR**: 관리자 대시보드, 비공개 사용자 페이지 (SEO 불필요)
:::
